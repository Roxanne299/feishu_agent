# 值班工具二期工时拆解（值班机器人 + 知识库）

> 口径：**人日**，1 人日 = 1 人 × 1 工作日。总量 **20 人日**。
> 投入：**1 人全职**，20 人日 ≈ 4 个自然周（已确认，排期按此口径）。
> 一期已交付：值班工具 magicshowbox（二期直接作为工具挂载，不重复计工时）。

---

## 一、总览

| 模块 | 人日 | 占比 |
|---|---|---|
| A. 机器人基建 | 5 | 25% |
| B. 知识库（大头） | 9 | 45% |
| C. 能力接入 + 机器人调优 | 6 | 30% |
| **合计** | **20** | 100% |

---

## 二、A. 机器人基建（5 人日）

| # | 子项 | 人日 | 说明 |
|---|---|---|---|
| A1 | 二期方案设计 + 索引规范定稿 | 0.5 | 机器人形态、知识库索引 schema、检索链路先拍定，避免返工 |
| A2 | IM 接入层 | 1.5 | 事件订阅、@触发、消息收发、话题/线程会话、卡片基础能力 |
| A3 | Agent 运行时 | 1.5 | 多轮会话状态存储、工具调用 loop、超时/并发/限流、错误兜底 |
| A4 | 工具与 MCP 接入框架 | 1 | MCP client 统一配置、工具注册与路由、**用户身份透传到工具侧**（权限不越权） |
| A5 | 可观测性 + 部署 | 0.5 | trace/token 统计、会话回放、beta→prod 灰度 |

**风险**：IM 平台应用创建/权限审批有流程周期 → 第 1 天就并行提申请，占自然日不占工时。

---

## 三、B. 知识库（9 人日）

| # | 子项 | 人日 | 说明 |
|---|---|---|---|
| B1 | 项目内索引目录生成器 | 2 | 扫描仓库产出结构化索引（模块、入口、领域概念、关键接口、依赖、owner）；LLM 辅助生成 + 人工校验 |
| B2 | 全局大索引 + 定时 git 同步 | 2 | 多项目注册表、定时拉取、增量更新、索引版本化；失败重试与告警 |
| B3 | 知识库 MCP Server | 3 | 检索工具：大索引路由到项目 → 项目索引定位模块 → 文件/片段级检索；**必须返回出处引用** |
| B4 | 索引更新 hooks | 1 | 代码改动后增量更新索引（优先走 CI / PR 合并后触发，而非每人本地装 git hook） |
| B5 | 试点项目接入 + 评测集 | 1 | 2 个试点项目全量接入 + 20~30 条真实值班问题作为回归集 |

**本期检索方案**：先做 **索引路由 + 关键词/BM25 + LLM 重排**，不上向量库。
理由：索引目录本身已承担语义压缩的职责，向量化会把工时推到 23+ 人日且运维成本高 → 放到 2.5 期。

**最大风险**：索引质量依赖各项目 owner 配合校验。建议本期只强推 2 个试点，把生成器和规范打磨好，三期再铺量。

---

## 四、C. 能力接入 + 机器人调优（6 人日）

| # | 子项 | 人日 | 说明 |
|---|---|---|---|
| C1 | 挂载知识库 MCP / 内部 skills / magicshowbox 工具 | 1 | 工具描述与选择策略，避免工具过多导致乱调 |
| C2 | 澄清阶段 | 2 | 意图分类 + 必填槽位缺失检测 + 多轮澄清策略 + 卡片化选项（而非纯文本追问） |
| C3 | 评测 + prompt/路由调优 | 2 | 基于 B5 回归集跑分，迭代 2~3 轮；关注"该澄清时不乱猜、该查库时不幻觉" |
| C4 | 可信度、转人工、上线 | 1 | 答案附引用、低置信度转人工、灰度放量、使用文档 |

## 五、排期（单人 20 个工作日）

| 阶段 | 工作日 | 内容 | 产出 |
|---|---|---|---|
| 第 1 周 | D1–D5 | A1–A5 | 机器人能在群里多轮对话、能调工具、有日志 |
| 第 2 周 | D6–D9 | B1–B2 | 单项目索引生成器 + 大索引定时同步跑通 |
| 第 3 周 | D10–D14 | B3–B5 | 知识库 MCP 可检索可引用 + hooks + 2 个试点 + 回归集 |
| 第 4 周 | D15–D20 | C1–C4 | 机器人接入全部能力、澄清可用、灰度上线 |

**里程碑**
- M1（D5）：机器人基建可用 —— 可对话、可调 magicshowbox
- M2（D14）：知识库可查 —— 2 个试点项目问答可追溯到代码
- M3（D20）：二期灰度上线 —— 澄清 + 知识库 + 工具闭环

---

## 六、本期明确不做（2.5 期）

1. 向量/语义召回升级（embedding + 混合检索）
2. 全量项目铺量接入（本期只 2 个试点）
3. 答案质量自动打分闭环
4. **值班结论回写知识库**（把每次值班的排查结论沉淀成知识）—— 这是让知识库自增长的关键，建议作为三期第一优先级
5. 多模态（日志截图、监控图解读）
